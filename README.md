# 电池应变、电压与电流监测软件

桌面上位机，使用 Python + Tkinter + Matplotlib，在 VS Code 中启动。只读读取采集软件已经写入磁盘的文件，支持“仅应变–时间”和“应变＋电压电流”两种绘图模式，同时显示同一应变文件内的 1～3 个通道。无需安装 Excel、Office 或 MATLAB。

## 本机立即运行

在 VS Code 中打开整个 `battery_monitor` 文件夹，在终端执行：

```powershell
.\.venv\Scripts\python.exe app.py
```

也可执行 `powershell -ExecutionPolicy Bypass -File .\run.ps1`，或安装 VS Code 的 Python/Python Debugger 扩展后，选择本文件夹 `.venv\Scripts\python.exe` 解释器，按 F5。这里的 Bypass 只作用于当前启动命令，不修改系统执行策略。

本机已创建独立 `.venv` 环境；没有向全局 Python 环境安装依赖。首次启动已预填本次提供的两个文件路径。

## 操作

1. 在左侧“数据与通道”中选择绘图内容。“仅应变–时间”只需选择应变文件，电池文件及两文件对齐设置会变灰且不参与读取；“应变＋电压电流”还需要选择电池文件。
2. 在三个应变通道框中选择最多 3 个不同通道。例如依次选择 `CH05`、`CH08`、`CH17`。只用一个通道时，将第二、第三个框设为“不选”。默认只选择 CH05。可从 CH01～CH20 下拉选择，也可输入 `CH08`、`8` 等编号；成功读取后下拉列表会更新为文件实际通道。重复通道会提示修改。更换通道组合后重新读取应变文件，多通道在同一次读取中解析，不为每个通道重复扫描整个文件。
3. 选择“原始微应变（保留初值）”或“Δ 微应变（减首值）”。该选项作用于所有所选通道，但每个通道分别减去自己的原始首值，再独立滤波和降采样。例如 CH05、CH08 的首值分别为 728、850 με，则分别减去 728 和 850，不能共用一个基准。基准在时间对齐裁剪之前确定，且随刷新保持不变。界面逐一显示各通道基准。此处是初值扣除，不是温度补偿。
4. 在左侧“滤波与时间”页选择应变输入采样率：自动、100、1，或直接填写自定义 Hz。默认输出为 1 Hz，可改成其他不超过输入频率的正数。参数多于窗口高度时，在侧栏滚动查看。
5. 点击“读取并绘图”，再次点击将读取最新已保存数据；也可开启自动刷新。刷新间隔从上次任务完成后开始计算，避免读取任务叠加。设置区保持可见，可用“隐藏设置 / 显示设置”按钮为图表腾出空间。底部“处理详情”可展开读取和滤波说明。
6. 图表上方“通道布局”可选择“同图叠加”或“分通道子图”。有图后切换立即生效，无需重读文件。其他采集和滤波参数仍需点击“读取并绘图”应用。
7. 可用图下工具栏缩放、平移、复位，或保存 PNG/PDF。导出 CSV 保留每条曲线自己的时间点，不强行插值到同一采样网格。

“同图叠加”将多个应变通道画在同一个应变纵轴上，用不同颜色和通道图例区分，适合比较同量程通道。所有通道采用相同的采样率与滤波参数。原始初值差异较大时，可选择 Δ 微应变比较变化量。

“分通道子图”每个应变通道单独占一行，纵轴独立自动定标，适合变化范围相差很大的通道。所有子图共用时间轴，在一个子图中缩放或平移时间范围，其他子图同步更新；各通道的纵轴互不绑定。只在最下方显示时间刻度和轴标题。单个通道也可使用此布局。

仅应变模式只有时间横轴与应变纵轴，以应变文件第一条记录为 0 秒，保留完整应变时段；不读取电池文件，不显示电压、电流或工步背景。切换回联合模式后恢复使用原来的电池文件及对齐设置。

联合模式选择“同图叠加”时，三个纵轴分别为左侧应变、右侧电压、右侧外侧电流；选择“分通道子图”时，各应变通道独立成行，底部另有电参数子图，电压在左轴、电流在右轴，仍与全部应变子图共用时间轴。各子图背景按 `record` 工作表中的工步类型划分：放电浅红、充电浅绿、搁置浅灰。工步切换以新工步首条记录为边界；末段着色截止于最新电池记录，不推测未来工步。未知工步不着色，并在说明区列出。时间间隔异常长的缺失段留白。

## 高分辨率显示

新版使用左侧分组设置、右侧图表的布局，设置区可滚动、可隐藏，处理日志按需展开。窗口大小和控件间距根据启动时屏幕的实际 DPI 调整，Matplotlib 使用高 DPI 画布，减少系统位图放大造成的模糊。只影响本程序，不修改 Windows 显示设置，也不影响正在运行的 Jupyter。

已在本机 2880×1800、200% 缩放下检查。窗口缩放时为时间轴标题保留实际留白，避免被工具栏裁切。跨不同缩放比例的显示器拖动尚未完整验证；若切换显示器后比例不合适，在目标显示器上重新启动程序。保存图片按独立导出尺寸与 240 DPI 渲染，保留当前坐标范围，不依赖当前窗口截图；PDF 可用于矢量输出。

## 时间对齐与采样频率

以下两文件时间对齐选项仅在联合模式生效。仅应变模式始终以应变首点计时，忽略两文件对齐及应变偏移设置。

### 默认：实际时间，共同起点

保留两个设备记录的日期时间，以较晚开始的文件作为共同显示起点，截去另一文件更早部分。两条时间轴均减去这个共同起点。数据末端各自显示到已读取的最新记录，不外推、不强制截齐末端。此模式要求设备时钟可比较。

“应变时间偏移 / s”可以修正已知的两设备时钟差，正数使应变曲线向后移动。程序不会通过曲线形状自动猜测时钟差。

### 可选：两文件首点对齐

分别将两个文件第一条记录作为 0 秒，再应用应变偏移。适合人为比较各自起始后的变化；即使原文件开始时刻相差数分钟，也会被强制对齐，不能据此认为两个事件实际同时发生。

### 电池标称 100 Hz 与文件保存频率

仪器采集频率固定为 100 Hz，并不保证导出的 Excel 每行都代表 0.01 秒。本次电池表 `test` 页“记录条件”实际为 `1s/0V/0A`，`record` 相邻正时间差中位数为 1 秒。

因此提供三个模式：

- **自动（优先总时间）**：以首条绝对时间为起点，加上 `总时间` 相对首条的变化；没有总时间列时使用绝对时间。对于本次午夜处的 1 秒绝对时间倒退，可以保持连续时间轴，并报告与绝对时间的最大差异。总时间倒退或无效时会停止并提示。
- **表内绝对时间**：直接使用每条绝对时间；若倒退则停止提示，避免悄悄重新排序。
- **固定 100 Hz 逐行重建**：第一行对应首条绝对时间，之后每行加 0.01 秒。仅用于确定每行都保存了一个原始采样点、且没有丢行的文件。对本次 1 秒保存一次的表格使用此项会错误压缩时间，不应选用。

应变自动判断通过时间间隔估计频率，接近 1 或 100 Hz 时采用该名义频率，偏差超过 25% 时要求手动输入。手动输入控制滤波与重采样网格，不覆盖原始记录的实际持续时间。遇到明显频率切换，建议按采集设置分段保存文件，分别处理。

## 应变预处理

处理顺序：校验时间和数值 → 根据显示选项减去原始首值 → 按真实时间插值到均匀输入网格 → 因果中值滤波 → 六阶 Butterworth 因果低通 → 在输出时间网格取值。

- 默认输入自动判断、输出 1 Hz、低通截止 0.2 Hz、中值 5 点。中值点数必须是 1～501 的奇数，填 1 关闭。
- 截止频率必须低于输入和输出频率各自的一半。填写 0 关闭额外平滑；若同时降采样，仍使用输出频率 0.4 倍的抗混叠低通，避免直接抽点。
- 使用因果滤波，不依赖未来尚未采集的记录。它会引入相位延迟，不能把滤波后的瞬态延迟直接解释为电池物理响应延迟。1 Hz 数据上的 5 点中值窗口约覆盖 5 秒，100 Hz 上约覆盖 0.05 秒，可根据实验调整。
- 采样间断超过 `max(5/输入Hz, 0.5秒)` 时分段处理，在图中留断点，重新初始化滤波；不跨长时间缺口插值。
- 同一时间戳的应变记录先合并均值。无效数值、时间倒退会提示并保留上一张成功图像，不悄悄删除错误记录。
- 不校正仪器漂移，不分离热应变，不自动消除缓慢变化。

## 采集中只读打开的行为

- 源文件使用只读句柄，并允许采集端继续写入或替换文件。不会通过 Excel COM 打开，也不会保存、覆盖源表。
- 本次应变 `.xls` 实际是 GB18030 编码的制表符分隔文本。首次读取整个已有文件，后续只解析新增完整行。尚未写完的最后一行留待下一次。缓存只保存所选 1～3 个通道的原始值和时间，不缓存全部 20 个通道。
- 文件缩短、替换、已读尾部变化或同尺寸覆盖保存，会触发重读。中间区域的原位修改同时伴随增长未必能被识别；若采集软件会修改历史行，请重新选择文件或重启程序以清空缓存。
- 真 XLS/XLSX 使用临时快照，快照前后检查文件大小、修改时间和文件标识。仅在文件更新后重新解析；正在保存或被独占时提示并保留旧图，下次刷新重试。临时快照使用完成即删除。
- “当前”指磁盘最新完整记录。采集软件尚未保存到磁盘、只存在内存的数据无法读取；如果采集软件采用独占锁，必须由采集软件允许共享读取或定期导出，程序不能绕过独占锁。
- 处理在后台线程进行；可取消读取。图像只在当前模式需要的文件均成功读取和处理后整体更新。联合模式下，两台设备各自的磁盘快照并非硬件同步采样。
- 原始数据全部参与处理。绘制超长曲线时使用分块极值压缩显示，导出数据仍保留全部处理结果。每次处理会重新过滤缓存中的所选应变通道；首次大文件及长记录刷新需要数秒。

## 支持的表格结构

应变：本次仪器格式的文本（`.xls` / `.txt` / `.tsv`，GB18030、第一列完整日期时间、后续 CH 通道），或首个工作表包含相同时间/通道布局的真 XLS/XLSX。配置区与表头自动跳过；不支持任意无日期 CSV 或仅有采样序号的应变表。

电池：XLS/XLSX 的 `record` 工作表，至少包含 `绝对时间`、`电压(V)`、`电流(A)`、`工步类型`。推荐有 `总时间`。兼容本次文件将工作表范围错误写为 A1:A1 的情况。工步背景来自 `record`，不依赖 `step` 页的汇总记录完成保存。

CSV 导出使用长表：`series`、`elapsed_s`、`value`、`unit`，并附带通道、该通道原始应变基准、对齐模式和起点。同一时间的三个通道对应三行，可按 `strain_channel` 筛选。仅应变模式只导出应变；联合模式另有电压、电流记录，这些记录的应变通道和基准留空。电压电流保留表内数值；应变为当前处理结果。它是查看数据导出，不是原始文件备份。

## 转移到其他电脑

复制整个 `battery_monitor` 文件夹；无需复制 `.venv`、`__pycache__`、`settings.json`、`last_error.log` 和 `validation`。不要直接搬运虚拟环境，它包含当前电脑的解释器路径。

目标电脑安装 **64 位 Python 3.12～3.14**，确保包含 Tcl/Tk（Python 官方 Windows 安装包的 Tcl/Tk 组件）。本机实际测试为 Python 3.14.6。随后在 VS Code 打开该文件夹，在 PowerShell 终端执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

也可执行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`；若系统 `python` 指向商店入口或不正确的解释器，使用 `-Python 'C:\实际路径\python.exe'` 指定。推荐迁移时用 `requirements.txt` 让包管理器选择适配目标 Python 的版本；与本机相同 Python 3.14/Windows 环境可使用 `requirements-lock.txt` 复现本次已安装的精确版本。其他 Python 版本尚未逐一实测。

| 直接依赖 | 用途 |
| --- | --- |
| numpy | 数组与时间计算 |
| scipy | 中值与低通滤波 |
| pandas | 大文本分块读取、时间解析、CSV 导出 |
| matplotlib | 三纵轴曲线、交互缩放与图像保存 |
| openpyxl | 只读 XLSX 读取 |
| xlrd | 旧版二进制 XLS 读取 |
| tkinter | 桌面界面，随 Python/Tcl/Tk 提供，无需 pip 安装 |

`requirements-lock.txt` 同时列出了上述包自动安装的间接依赖。运行时无需网络。

若目标电脑离线，可先在相同 Windows 架构、相同 Python 版本的联网电脑准备依赖包：

```powershell
python -m pip download -r requirements-lock.txt -d wheels
```

把 `wheels` 文件夹一起复制后，在目标环境安装：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheels -r requirements-lock.txt
```
